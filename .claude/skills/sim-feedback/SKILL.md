# シミュレーションのフィードバック（ユーザーの指摘と決定）

答え合わせや調整案を出す前に、この一覧を上から読み、**「何を指摘されたか」「なぜそう決めたか」を自分の言葉で要約してから**作業を始めること。
ここにある決定に反する調整案は出さない（変えたいときは、理由を添えてユーザーに確認する）。
新しい指摘を受けたら、この一覧の該当する見出しの末尾に日付つきで追記する（CLAUDE.md には書かない。2026-11-05 ユーザー指定）。

## 1. 答え合わせのやり方
- **答え合わせは毎月5日に前月分を行う。** 5日には前月の請求・コンテンツ管理表（進行管理）の更新が終わっているので、その後でないと意味がない。月の途中の数字で判定しない。（2026-11-05）
- 予測は、毎月その月に最初にシミュレーション画面を開いたときに、記事目標どおりの予測（理想・現実的・悲観）を BigQuery `best_media.sim_predictions` に保存する。比べるのは「理想」＝画面の「シミュレーション結果」。
- 要素はつながりの順に見る：記事数 → PV → CV率 → コール率 → 成約率 → 1成約あたりの収益。±20%をこえた最初の要素を「ずれの起点」とし、そこを直す案を出す。件数が少ない要素は判定しない。
- 画面には「どの要素がずれたか」「何を直す・調整するか」「どのAIが答えを出したか」を出す。（2026-11-05）
- 計算ルールを変えたときは、その月の保存済み予測を消して保存し直す（消す前の行は scratchpad に残す）。
- 置き場所は設計図どおり：原本＝BigQuery、AIの作業机＝Supabase（答え合わせの表・AIの提案・あなたの判断と理由・AIの費用の記録）。Supabase は毎日 BigQuery から写す。（2026-11-05）
- いまは内ループ：AIの調整案に、ユーザーが画面で OK／却下と理由をつける。**却下された案と理由（sim_decisions）を毎回読み、同じ案をくり返さない。** AIが見るのはずれが大きい項目だけ（費用を少なく）。

## 2. 見せ方
- シミュレーションは「理想」だけを「シミュレーション結果」として見せる。メディアとディレクトリを選べる。
- 月ごとの表は**サマリと同じ項目をすべて**出す（PV・セッション・ユーザー・アクティブユーザーあたりのビュー・CV・CV率・表示回数・クリック数・平均掲載順位・公開記事数・新規・リライト・残りの新規KW・簡易リライト・微調整・コール・成約・収益・支出・収支・1記事あたりの単価）。予測していない項目を残さない。（2026-11-05）
- 「うち新規KWが尽きてリライトに回した本数」の行はいらない。補足の注記も不要。
- 計画表は実際に使う3行（新規・リライト・簡易リライト）だけ。入力欄は目標があるところだけ。
- グラフは指標をプルダウンで選ぶ。実績＝青、シミュレーション＝赤。
- シミュレーション比較はサマリと同じ作り（達成率を大きく、PV・CV・コール・収益・記事制作数）。メディア累計のときはメディアごとの達成率も出す。前年比は同じ日数どうしで比べる（月の途中を月全体と比べない）。
- 損益分岐（月ごと・累計、5年）を出す。

## 3. 記事数のルール
- 目標がない月：目標が入っているメディアはその目標の平均、目標がないメディアは直近6か月の実績の平均（ディレクトリ目標のメディアはディレクトリごと）。
- 計画表・取り込みのデータは「参考」と言われただけ。**ダッシュボード（記事目標）には反映しない。** 2026/04以降の取り込み分は削除済み。（2026-11-05）
- 新規は、コンテンツ進行管理の未公開の新規KWの数が上限。尽きた分はリライトに回す（カギお助け本舗は回さない）。
- カギお助け本舗：リライト月10本。
- ガラスお助け本舗：カギお助け本舗の新規KWが尽きるまで新規0本、その翌月から月10本。
- BEST365：2027/04以降は新規・リライト・簡易リライトとも0本（運用停止）。
- 害虫害獣コンシェルジュの新規：2026/11〜12月は月10本、2027/01〜04月は月12本、2027/05以降は月14本。ディレクトリはもとの割合で分け、細かいディレクトリの合計をメディアの本数にそろえる。（2026-11-05）

## 4. 率を借りるメディア
- 害虫害獣コンシェルジュ：収益の率はハチお助け本舗（害獣の側は害獣お助け本舗）。ゴキブリ・シロアリ・その他害虫はシロアリお助け本舗。
- 屋根外壁お助け本舗：CV・収益はシロアリお助け本舗。
- シロアリお助け本舗・ハチお助け本舗：CVのあと（コール率・成約率・1成約あたりの収益）は害獣お助け本舗。

## 5. 季節性・検索ボリューム
- 季節性は Ahrefs の代表KWの月別ボリュームから出す。KWごとの中央値の4倍超・1/4未満の月（はね）は除く。どのメディアも季節性が効いているか確かめる。（ネズミの5月のはねは指摘済み）

## 6. お金
- 支出は SEO数値管理シートの値を使わない。業務委託・人件費などから計算した値（settings/expense_computed）を使う。（2026-11-05 指摘：シートの値を使っていた）
- 1記事あたりの単価＝支出÷（新規＋リライト＋簡易リライト）。
- Ahrefs の費用は50%（残りはくらしのレスキュー）。

## 7. 作業の姿勢（指摘されたこと）
- 1か所ずつ直して終わりにしない。指摘を受けたら関連するところを全部見直してから報告する（「ミスが多すぎる」と指摘あり）。
- 数字の比較は表で示す。返答はすべて日本語。
- AIの費用（トークン）はできるだけ少なく、精度を上げる。AIを使ったら、どのAIが出した答えかを残す。

## 8. 精度の基準とチーム（2026-11-06 ユーザー指定）
- 精度のゴールは「予測と実績の完全一致」ではない。**「がんばれば届く、でも無謀ではない」目標**になっていること。
  - 実績÷予測が **85%〜110%＝ちょうどいい背伸び**（精度に数える）。85%未満＝目標が高すぎ（無謀）、110%超＝低すぎ（甘い）。
  - 「届いた月（100%以上）」は半分くらい（3〜6割）が理想。いつも届く＝甘い、ほとんど届かない＝無謀。
  - 見る項目は 記事数・PV・収益。精度＝帯に入った（メディア×項目）の割合。目標70%以上。
- 費用（トークン）は前の月より減らす（KPIはそのまま）。数えるのはこのループで使った分だけ（ai_cost_log の run_id・loop）。
- チームは シュミレ・クロード指揮官（Claude）／シュミレ・クロード検証（sim-checker・Claude）／シュミレ・ジェミニ探索（Gemini）／シュミレ・オープン検閲（OpenAI）。サブエージェントには全部を渡さず、編集長が必要な分だけを切り出して渡す（sim_check_fs.js の slice）。Supabase は sim_check_fs.js を通してだけ読み書きし、だれが何を読んだかを残す。
