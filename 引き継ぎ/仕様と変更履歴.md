## 4. 主な仕様（決まっていること）

### 記事管理
- 元データ：各メディアの記事管理シート → `importArticleSheets` → BigQuery `article_items`。どのシート・タブを読むかは `articles.gs` の `ARTICLE_SHEET_DEFAULTS`（設定タブ「記事管理シート」に自動で行が入る）。見出し行は先頭6行（なければ30行）から自動で探す。
- メディア別の特記：
  - 水まわり：トイレ／洗面台／過去制作|BEST365移管。洗面台は空欄状況でも記事URL＋構成URL＋ライティングURLがそろったら完了。
  - BEST365：水回り①②・カギ・外壁屋根・電気設備（外壁屋根・電気設備は停止＝全記事移管済み）。進行状況に記事移管中／記事移管完了。
  - 屋根外壁：屋根 No.001〜028・外壁 301〜313 は「BEST365から移管」。
  - ガラス：進行中・過去記事・過去記事②（先のタブと同じ記事URLは除外。依頼シートURL＝構成URL）。
  - 害獣：タブ「害獣お助け本舗」の15行目から（上は集計表）。ディレクトリは「記事テーマ」列（ネズミ駆除〜害獣駆除）。進行状況は執筆／アップロードの進行状況から。設計シート（タブ名）はそのタブへのリンクに変換。設計完了の記事のディレクション担当は「日比野」。
  - 害虫害獣コンシェルジュ：ハチ・コウモリ・ネズミ・その他害獣のタブ（ゴキブリ・シロアリ・その他害虫はディレクトリのみ）。KWだけの行・No.だけの空き枠は取り込まない。
- 読み替え（app.js）：最終化→完了、構成レビュー中→構成作成完了、記事レビュー中→記事執筆完了、監修者確認完了→記事監修者確認、監修者確認中→構成監修者確認 など（`STATUS_ALIAS`）。制作判断は新規・リライト・簡易リライトに統一（`typeAlias`）。
- 進行管理：新規はNo.必須、リライトは元記事からNo.を入れる。緊急性（高中低）・ターゲット層・クエリタイプ・ポジションは構成作成完了以降の必須項目。一括操作（チェックボックス）あり。
- 本数の数え方：**新規・リライト・簡易リライトは進行管理のアップロード日で数える**（未来の日付と移管は数えない）。微調整＝WordPressで更新された記事 −（リライト＋簡易リライト）。WordPressで公開された新規記事が進行管理より多いときだけ進行管理の上にアラート。

### KW追従（Ahrefs）
- 進行管理で完了の記事のKWを毎週 Rank Tracker に登録（メディアごとのプロジェクトは自動作成）。Rank Tracker のKW上限に達したら入るところまで入れて、未登録件数を表示（2026-10-10 時点で上限250件、未登録812件。ユーザーがプラン変更予定）。
- 毎月2日に前月末の順位（スマホ・PC）を取得。画面は記事（赤＝進行管理と合わない）・最新のアクション・検索KW・検索Vol・KD・PV/CV（GA4ページ別）・月ごとの順位。チェックボックスで選んでリライト候補（KWごとにリライト／簡易リライト）を進行管理に追加。

### CTA・訴求ブロック・記事用コンテンツ（2026-10-26 ユーザー指定）

### もしもアフィリエイト（2026-10-14 作成）
- 公開APIがないので、管理画面の「成果報酬レポート（月別）」のCSV（Shift_JIS）を、収益管理 →「もしもアフィリエイト」から取り込む。メディア全体／メディアごとを選んで取り込む。
- BigQuery `moshimo_monthly` に追記し、月・メディアごとに最後の取り込みを使う。取り込みは管理者か収益管理の編集権限の人だけ。
- 収益は**承認成果金額**、発生成果金額は参考で並べる。金額は税込みなので **÷1.1 で税抜き**（ユーザー指定）。
- スプレッドシートの「アフィリエイト」の値も税込みなので、表示は÷1.1（ユーザー指定）。CSVを取り込んだ月・メディアは、シートの「アフィリエイト」の行より**CSVを優先**（月次・日次・サマリ）。メディア全体のCSVはメディアに分けられないので、収益の集計には使わず「メディア未割当」の確認に使う。
- 自動取得（2026-10-14 ユーザー指定）：Cloud Scheduler `moshimo-collect`（毎月2日・15日 5:30）→ `/tasks/moshimo`。ログイン（`/af/shop/login/execute`、ID・パスワードは Secret Manager `moshimo-login`）→ `/af/shop/report/payment/monthly/download` に shop_site_id（空＝全体）・year を POST して、直近3か月分を取り込む。**ダウンロードの前に同じ条件で `/af/shop/report/payment/monthly` に POST（レポート表示）しないと、メディアを選んでも全体の数字が返る**（2026-10-14 確認。メディアの数字が全部全体と同じなら保存しない安全確認あり）。もしも側のメディア名とダッシュボードのメディア名が同じなので名前で対応づけ（生活お助けはもしもに登録なし）。
- API・連携設定の「過去分をすべて取得」で、もしもの画面で選べる年（2021年〜）の全部を取り込める（すべて0の月は保存しない。ユーザー指定）。定期実行は直近3か月だけ。
- 規約（メディア利用規約）に自動取得の禁止はない。ログインに画像認証・二段階認証が出たら止める（突破しない）。

### 収益管理のタブ（2026-10-14 ユーザー指定）

## 2026-11-05 CTA・訴求ブロックのプルダウンの重複をなくす（v1.486／app.js?v=463）
